# Quant Agent 监控与告警运行手册

## 1. 监控范围

- 数据：行情、财务、事件、账户快照和核对输入的完成度；
- 服务：成功率、请求数、累计延迟和最大延迟；
- 风控：服务可用性、拒绝数量和 Kill Switch 状态；
- 订单：成功提交、幂等键冲突导致的重复下单风险；
- 核对：订单、成交、现金和持仓差异，按 INFO、WARNING、CRITICAL 汇总。

指标只使用预定义的低基数标签，不写入账户、用户、令牌、密钥或自由文本。API 通过
`/internal/metrics` 输出 Prometheus 文本；部署时只能在内部网络抓取，不应公开到
互联网。

## 2. 告警等级与路由

| 等级 | 响应目标 | 默认路由 |
|---|---|---|
| P0 | 立即停止风险扩散并双人处置 | incident-primary、risk-lead |
| P1 | 当班人员立即诊断，交易保持失败关闭 | risk-oncall、platform-oncall |
| P2 | 当班周期内修复或确认降级 | data-platform、operations |
| P3 | 进入日常运营复核 | operations-review |

相同告警指纹默认 15 分钟内去重。告警必须包含策略 ID、固定摘要、来源、运行手册、
安全诊断字段和发生时间。

## P0 重复下单风险

保持订单提交拒绝，不得人工绕过幂等约束；核对幂等键哈希、草案 ID 和最近提交审计，
确认没有第二笔订单进入执行层。必要时开启账户 Kill Switch。

## P0 严重账实差异

立即开启相关账户 Kill Switch，冻结新订单；分别核对订单、成交回报、现金和持仓快照，
保留原始快照哈希并由 RiskAdmin 与运营双人确认。

## P1 风控不可用

所有交易变更保持失败关闭。检查风控服务健康、配置版本和依赖数据；恢复后先运行固定
风险用例，再由 RiskAdmin 解除门禁。

## P1 Kill Switch 开启

确认触发范围、触发人和事故快照。只有 RiskAdmin 在复核数据、账户、未完成订单和告警
后才能执行恢复；Agent 无权恢复。

## P2 数据完成度不足

检查缺失交易日、标的、财务期或账户字段；禁止依赖任务继续运行。补数后重新执行质量
校验，不允许仅修改阈值消除告警。

## P2 服务健康度

检查最近错误、任务积压、数据库连接和外部依赖。以路由模板而非真实账户或资源 ID
聚合，避免高基数和敏感信息泄漏。

## P2 一般账实差异

检查部分成交、回报延迟和容差设置。差异升级为 CRITICAL 时按 P0 处理。

## P3 风控拒绝升高

在日常运营复核中检查拒绝原因分布、策略变更和数据质量，不降低风险阈值来消除告警。

## 3. 测试送达

执行告警测试时使用内存或测试 JSONL 接收器，不连接真实值班渠道。验收必须覆盖
P0～P3 路由、15 分钟去重、定位字段、运行手册和敏感字段脱敏。
