# P8 系统验证报告

## 验证边界

本轮只完成无需外部生产资源、可在本地确定性验收的 P8-T01 至 P8-T04。P8-T05
依赖尚未由 GitHub 远程运行结果确认的 P0-T07，因此部署、监控、影子运行、三个月
模拟盘、券商合规和小资金实盘辅助均未提前启动。

## 端到端环境

- 固定数据位于 `tests/e2e/fixtures/market_day.json`；
- 运行模式被锁定为 `PAPER`，Broker 必须为 `fake`；
- 每次运行前重建账户与 Broker，运行后清除内存状态；
- 连续运行两次并比较完整结果与内容哈希；
- 失败时仅在 `artifacts/e2e/failure.json` 保存诊断信息；
- 命令：`python -m tests.e2e.runner`。

## 黄金场景

十二个 Harness 场景都有固定预期、检查点和机器可读结果。重点安全断言包括：

- 坏数据不得生成订单；
- 未审批、审批过期或审批后价格偏离不得提交；
- Broker 超时后的重试必须复用幂等键；
- 部分成交差异必须成为核对事件；
- 模拟盘与实盘配置不得串用；
- 用户和 Agent 均不得跳过风控。

命令：`python -m tests.replay.runner`。

## 安全验收

审批仅允许 `APPROVER`；Agent 不能批准订单或恢复 Kill Switch。外部内容按不可信
数据隔离，用户指令不能切换服务端模式，响应中的凭证与账号会被脱敏。代码扫描
覆盖 `apps/` 与 `packages/` 的 Python 运行时代码。本轮未发现未关闭的高危缺陷。

命令：`python -m pytest tests/security`。

## 性能与容量

验收工具记录中位数和 P95，检查重复工作负载后的保留内存，并按 6,000 个标的、
252 个交易日、每行 512 字节估算至少一年的日线容量。收盘后作业预算设为 12 小时，
确保在下一交易日前完成。实际测量结果由运行环境生成，不在文档中固化虚假的统一
数字。

命令：`python -m tests.performance.runner`。
